# Yuki · 素材外链与 AI 对话输出规则

这份文件是供后续生成对话时使用的模板。立绘由四种形态、十二种表情与动作组成，共 **48 张独立竖版透明 PNG**。角色立绘图片不含场景背景；示例复用本仓库已有背景与玩家素材。

## 一、素材目录与外链

```text
Yuki/立绘/萝莉形态/表情.png
Yuki/立绘/少女形态/表情.png
Yuki/立绘/御姐形态/表情.png
Yuki/立绘/病娇御姐形态/表情.png
```

外链前缀：

```text
jsDelivr：https://cdn.jsdelivr.net/gh/karina-zzya/AI-assets@main/
GitHub Raw：https://raw.githubusercontent.com/karina-zzya/AI-assets/main/
```

可使用下表已经编码的完整链接；不要把 GitHub 的 `blob/main` 文件预览页放进 `img.src`。路径与文件名区分大小写，不要自行翻译或增删字符。CDN 地址暂不可用时，可用同一条目的 GitHub Raw 地址。需要锁定某次上传的版本时，将 CDN 的 `@main` 或 Raw 的 `/main/` 替换成该次提交 SHA。

尺寸以 [assets.json](./assets.json) 为准：47 张为 1024×1536，1 张为 1024×1535，均为竖版且带 alpha 透明通道。

## 二、先选形态，再选情绪与动作

鲜血饱食度 A 为 0～100 的整数，形态只由 A 决定。这里的 A 是角色剧情状态，不是使用者年龄或现实属性。

| A 区间 | 形态目录 | 本套设计参考身高 | 服装识别 |
| --- | --- | --- | --- |
| 0～29 | 萝莉形态 | 136 cm | 黑红哥特裙、黑色连裤袜、乐福鞋 |
| 30～69 | 少女形态 | 164 cm | 淡黄格纹衬衫、深灰裙、白色凉鞋 |
| 70～94 | 御姐形态 | 178 cm | 米白高领毛衣、亚麻色长裤、棕色风衣 |
| 95～100 | 病娇御姐形态 | 194 cm | 黑红花纹旗袍、铺地长发 |

每种形态都有同名的十二张图。未交代 A 时，沿用最近一次已确认的形态；形态也未建立时，先在正文明确采用的形态，再用图，不要假造 A 数值。好感、害羞、生气等情绪不改变形态。示例固定使用少女形态，并不代表所有场景默认使用少女形态。

| 文件名 | 选择依据 |
| --- | --- |
| 开心.png | 明显喜悦、被满足、欢迎或庆祝。 |
| 微笑.png | 日常温和回应、轻松交流，情绪幅度低于开心。 |
| 难过.png | 低落、失望；尚未明确哭泣。 |
| 流泪.png | 正文明确出现哭泣、落泪或擦泪。 |
| 生气.png | 不满、皱眉、鼓脸、抱臂。 |
| 害羞.png | 脸红、移开视线、局促或扭捏。 |
| 待机.png | 未指定情绪、倾听、普通站立；缺少依据时的默认值。 |
| 无奈.png | 叹气、摊手、认命或被折腾后的反应。 |
| 苦笑.png | 尴尬、自嘲、勉强带笑，不能简单替代微笑。 |
| 喂饭.png | 正文确实发生端碗递勺或喂饭动作；仅聊到吃饭不能选。 |
| 背手回头.png | 正文确实发生背手、转身回望的动作。 |
| 狡黠.png | 调皮、故意逗弄、有小主意、意味深长的小得意。 |

本套实际文件名是 `开心.png` 与 `背手回头.png`；旧模板里的 `开心挥手.png`、`背手回眸.png` 不是本套路径。原本地目录“娇小形态”对应仓库“萝莉形态”，“高挑形态”对应“病娇御姐形态”。不要把目录别名直接拼进图片 URL。

## 四、交给 AI 的输出规则

1. 只有角色在当前场景出现、且正文情绪或动作有依据时，才插入相应立绘。组件放在正文中间，作为补充；不要用组件完全代替正文，也不要无依据连续堆图。
2. 先根据已确认的 A 或形态确定目录，再根据当前情绪与动作选文件。与该步无关的动作图不可随意使用。未知情绪用“待机”。
3. 一段组件只用一个外层 `<div class="yuki-dg" id="yuki-dgN">`；`<style>` 必须是外层 div 的第一个子元素，每段自带完整样式，不依赖其他消息。
4. **生成组件本身时只输出 HTML 代码**，不夹带说明、表格或 HTML 注释。文章正文放在组件外。不要输出 `html/head/body` 标签，也不使用 JavaScript、事件处理属性或外部脚本。
5. 第 N 段使用 `id="yuki-dgN"`，该段的 radio 共用 `name="yuki-dgN"`。不同段的组名必须不同。第 M 步用 `id="yuki-dgN-M"`，所有元素 id 在整页唯一；`label.for` 必须指向同段真实存在的步骤 id。
6. 新增一段时同步替换根 id、radio name、步骤 id、label.for，以及动画名 `yuki-dgN-in`。不要只改其中一处。第一步必须带 `checked`。
7. 每步保持 `input.dg-s` 紧邻其后的 `div.dg-step`，中间不能插入其他元素。显示逻辑依赖相邻选择器 `+`。
8. 角色说话用 `dg-speak-role`，玩家说话用 `dg-speak-player`。说话者高亮，另一方变暗。表情差分只替换 `img.dg-role` 的 `src` 和对应 alt。
9. 普通步骤用 `label.dg-hit` 指向下一步；末步只保留“重新开始”按钮，指向本段第一步，按钮延迟 1.2 秒出现。
10. 所有图片链接必须来自本表、assets.json 或仓库确实存在的资源；不要编造链接。示例中的 `{{user}}` 是运行环境的玩家名变量，应保留；它不是未替换的素材地址占位符。
11. 立绘必须使用 `object-fit:contain` 并保持宽高比，完整保留头发、鞋底及手部；不可用 `object-fit:cover` 裁切立绘，也不要给透明 PNG 加实色底。只有背景图片使用 `object-fit:cover`。
12. 每段建议 3～6 步；每步台词建议不超过 60 个中文字符，长台词拆步。正文可以充分展开。玩家立绘可整行删去，角色列再按需要居中。
13. 目标环境必须允许 HTML、`style`、`input`、`label` 和外链图片。平台过滤其中元素时，先确认平台能力；不要声称所有聊天平台都支持。
